# Metron `v0.1.0-alpha.1` Release Notes

**Status:** Pre-release (`alpha.1`) · **Toolchain:** Stable Rust `1.100.0` (Edition `2024`)

## Highlights

- **Two-lane zero-bubblewrap sandbox (`crates/metron-sandbox`, [ADR 0029](../adr/0029-wasmtime-aot-landlock-seccomp-sandbox.md)):**
  - **Lane B (`native_jail`):** Replaces `ToolId::Bubblewrap` (`bwrap`) and 512 MiB `Image::stage` disk copies with unprivileged `systemd-run --user --collect` cgroup v2 (`MemoryMax`, `MemorySwapMax=0`, `TasksMax`, `CPUQuota`, `KillMode=control-group`, `PATH`/override tool resolution, typed `InsufficientScratchSpace`), hardened direct-supervisor fallback (`RLIMIT_AS`, `RLIMIT_CPU`, `RLIMIT_FSIZE`, `RLIMIT_NPROC`, `RLIMIT_NOFILE`, `PR_SET_PDEATHSIG(SIGKILL)`, real wall-clock `SIGKILL` timeout), rootless namespace isolation (`CLONE_NEWUSER | CLONE_NEWNET | CLONE_NEWIPC | CLONE_NEWUTS` with explicit receipt attestation and no silent degradation), pre-exec `/proc/self/fd` hygiene fail-closed check, strict `CompatLevel::HardRequirement` `landlock 0.4.8` (strict `/proc/self` read-only without broad `/proc` execute, typed `LandlockInsufficient`), expanded `seccompiler 0.5.0` BPF filtering (`clone3 -> ENOSYS`, `clone(CLONE_NEW*)`, `kexec_file_load`, `open_by_handle_at`/`name_to_handle_at`, `process_vm_readv`/`writev`, `personality`, `kcmp`, `syslog`, SysV IPC, `AF_VSOCK`/`AF_BLUETOOTH`/`AF_ALG`/`AF_XDP`, and default-blocked `AF_UNIX`), and direct `F_SEAL_WRITE`-sealed `memfd` execution (`/proc/self/fd/<n>`).
  - **Lane A (`wasm_aot`):** Splits offline Cranelift AOT compilation (`metron-wasm-compiler`, `--features compiler`, itself jailed under Landlock read-only input + write-only output dir + zero-network seccomp before invoking Cranelift) from the zero-Cranelift runtime host (`wasmtime 51` + `wasmtime-wasi 51` with `InstanceAllocationStrategy::Pooling`, warm `LaneARuntime` + shared epoch ticker thread), enforcing zero-key-on-disk anonymous pipe delivery + parent pre-verification, two-phase seccomp (baseline pre-deserialize + stacked W^X `PROT_EXEC` post-deserialize), hardened direct-child timeout/`rlimit`, deterministic `consume_fuel(true)`, `epoch_interruption(true)`, `StoreLimits`, and deterministic `(fuel_consumed, peak_memory_bytes)` `ResourceReceipt` emission.
- **Minimal audited `unsafe_code` boundary (`crates/metron-wasm-aot-loader`):**
  - Single `< 80`-line crate (`src/lib.rs`) pinned by `tests/architecture` as the sole `unsafe_code` exception in the workspace.
  - Validates `F_SEAL_WRITE | F_SEAL_GROW | F_SEAL_SHRINK | F_SEAL_SEAL` memfd seals, streaming BLAKE3 digest, `(wasmtime_version, target_triple, engine_tunables_digest, cwasm_blake3)`, and constant-time domain-separated HMAC-SHA256 tag **before** calling `unsafe { Component::deserialize_file }`.
- **Typed `rmcp 3.11` MCP bridge & wired `metron-host` runtime (`crates/metron-mcp`, `crates/metron-host`, [ADR 0030](../adr/0030-model-provider-and-rmcp-boundary.md)):**
  - Exposes `MetronMcpServer` (`rmcp::ServerHandler`) and `MetronMcpClient` with pre-sandbox JSON Schema argument validation, live `RequestContext` `notifications/cancelled` child-kill propagation, bounded poison-safe receipt ring buffer, and durable `ReceiptSink` (`SqliteReceiptSink`) persistence directly into `metron-store-sqlite`.
  - Wires `ModelBackend::Http(HttpModelProvider)` alongside `Native`/`Script`, `McpToolDispatcher` + `LaneAWasm` behind `AuthorizedEffect`, and indexed `intents(task_id, status)` SQLite queries with durable `external_receipts` storage.
- **Pluggable HTTP `ModelProvider` + optional `local-cuda` (`crates/metron-provider-http`, `crates/metron-inference-worker`):**
  - Day-1 OpenAI Chat Completions (`/v1/chat/completions`) and Anthropic Messages (`/v1/messages`) HTTP adapter supporting `MessageRole::Tool`, `ToolDefinition`/`ToolCall`, `response_format` JSON schema, `cache_control` prefix markers, deterministic model token-cost pricing (`spend_micros_usd`), incremental SSE streaming (`complete_stream`), exponential backoff with `Retry-After` + circuit breaker on `429`/`5xx`, redirect disablement, response byte caps, secret redaction, and `ResourceReceipt` preservation on both success and `Transport`/`Upstream` failures.
  - `mistralrs` moved behind optional `local-cuda` / `local-cpu` Cargo features so `cargo test --workspace --locked` builds and passes cleanly without GPU hardware or model weights.
- **Governance & Release Provenance:**
  - Single-branch `main` workflow with `.github/CODEOWNERS` (`* @kmosoti`), SHA-pinned CI and release workflows (`.tar.zst`, `.deb`, `SHA256SUMS`, `RELEASE-EVIDENCE.json`, and `actions/attest-build-provenance`), and zero Python in product/CI scripts.

## Scope & Known Limits

- Local quantized `mistralrs` inference remains gated behind `--features local-cuda` (or `--features local-cpu`) in `crates/metron-inference-worker` and requires compatible GPU/model artifacts at runtime.
- Hardware-backed native coding acceptance gates remain tracked in [Issue #7](https://github.com/kmosoti/Metron/issues/7).
