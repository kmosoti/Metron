# Metron `v0.1.1-alpha.1` Release Notes

**Status:** Pre-release (`alpha.1`) · **Toolchain:** Stable Rust `1.100.0` (Edition `2024`)

## Security Hardening & Release Governance

- **Security Policy & Trust Boundaries ([`SECURITY.md`](../../SECURITY.md)):**
  - Documents supported alpha versions, private vulnerability reporting, and explicit trust boundaries across Lane A (`wasmtime 51` AOT + `< 80`-line `crates/metron-wasm-aot-loader/src/lib.rs`), Lane B (`metron-jail` Landlock/seccomp/cgroup confinement), `metron-mcp` (`rmcp 3.11`), `metron-provider-http`, and out-of-scope threat model assumptions.
- **Release Pipeline Provenance & Protected-`main` Guard (`.github/workflows/release.yml`):**
  - Replaces hardcoded `v0.1.0-alpha.1` release notes path with dynamic `docs/releases/${{ github.ref_name }}.md` lookup backed by full repository checkout (`fetch-depth: 0`).
  - Adds fail-closed protected-`main` ancestry checks (`git merge-base --is-ancestor "${GITHUB_SHA}" refs/remotes/origin/main`), release notes existence checks, `[workspace.package] version` parity verification, and `workflow_dispatch` tag-format validation before artifact build and publication on tag pushes.
  - Preserves 40-hex commit SHA pinning across all CI and release GitHub Actions.
- **HTTP Model Provider Hardening (`crates/metron-provider-http`):**
  - Enforces strict `base_url` validation rejecting malformed authorities, embedded userinfo (`@`), query/fragment strings, obfuscated numeric host literals, unspecified/multicast/link-local IPs (`0.0.0.0`, `::`, `169.254.0.0/16`, `fe80::/10`), and cloud metadata hostnames (`metadata.google.internal`), while permitting explicit local loopback endpoints (`127.0.0.1`, `::1`, `localhost`).
  - Replaces unbounded `resp.bytes().await` buffering in both standard execution and non-2xx streaming error paths with chunk-wise `read_bounded_body` enforcing `max_response_bytes` strictly per chunk (plus upfront `Content-Length` checks and checked byte arithmetic).
  - Hardens incremental SSE parsing against split multi-byte UTF-8 chunk boundaries, checked tool-call index parsing, and overflow-safe circuit-breaker cooldown calculation.
- **MCP Bridge Bounds & Registration Hygiene (`crates/metron-mcp`):**
  - Adds bounded recursive JSON Schema validation (`MAX_SCHEMA_DEPTH = 16`, supporting nested `object` and `array` constraints) and pre-sandbox serialized JSON payload bounds (`MAX_MCP_ARGS_BYTES = 1 MiB`) before allocating sandbox pipes/`memfd`.
  - Validates tool names, non-empty Lane A `.cwasm` payloads, absolute paths + 64-hex lowercase `sha256` digests on `LaneBNative` registration, and fail-closed `checked_add` sequence counters.
- **Two-Lane Sandbox Input/Control Hygiene (`crates/metron-sandbox`):**
  - Validates systemd unit names (`validate_unit_name`) and `XDG_RUNTIME_DIR` / cgroup paths to block path traversal and `--unit=` CLI option injection.
  - Shares `read_bounded_regular_file` (`O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC`, regular-file `is_file()` verification, strict byte ceiling rejection) across `metron-jail`, Lane A `wasm_aot_jail`, and `metron-wasm-compiler`; uses exclusive `O_CREAT | O_EXCL | O_NOFOLLOW` (`0600`) receipt creation; and caps Lane A stdin `memfd` streaming directly to `spec.max_cwasm_bytes`.
- **Host Safety Hardening (`crates/metron-host`):**
  - Fixes saturating arithmetic on decision-step budget calculation in `coding_contract`, bounds `HttpProviderSettings.max_response_bytes` and `api_key_env` names, and enforces non-blocking regular-file checks in `model_cli` and `resource_budget` input readers.

## Scope & Known Limits

- Local quantized `mistralrs` inference remains gated behind `--features local-cuda` (or `--features local-cpu`) in `crates/metron-inference-worker` and requires compatible GPU/model artifacts at runtime.
- Hardware-backed native coding acceptance gates remain tracked in [Issue #7](https://github.com/kmosoti/Metron/issues/7).
